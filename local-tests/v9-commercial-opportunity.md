# v9 Kappa — commercial opportunity (hypotheses, no market research)

All willingness-to-pay figures are hypotheses to validate in a pilot,
not findings. No market statistics are claimed.

## Segments

1. Independent developers (long-lived projects): problem is frequent
   (machine loss, stale checkouts) and severe when it hits; existing
   alternative is manual archaeology. Trigger: failed rebuild.
   Hypothesis: low single-user price tolerable. NAS fit: project
   archive already on the device.
2. Small software teams: handover readiness + onboarding ("can a new
   hire build this?"). Trigger: failed onboarding week. Hypothesis:
   team-seat model. Risk: support burden for false blockers.
3. Creative studios (fragmented assets): missing linked assets block
   renders. Trigger: deadline-day missing file. Hypothesis: project
   addon. Integration: asset paths, not code deps — needs work.
4. IT consultants (customer handovers): readiness passport as a
   deliverable artifact. Trigger: handover sign-off. Hypothesis:
   per-report value. Liability: passport must never imply restore.
5. SMBs (critical data on NAS): audit preparation, continuity story.
   Trigger: audit or insurance request. Hypothesis: OEM bundle.

## Strongest initial segment + model

IT consultants + SMB audit prep: the Readiness Passport is already a
document artifact, the buyer (not the end user) pays, and UGREEN NAS
is the natural channel (data at rest on the device). Model: Skills
Hub listing (free assessment, paid team/passport-pack) or OEM bundle
for business NAS lines. Requires: NAS validation, UX hardening,
liability review of passport wording.

## Defensibility

Evidence discipline (fail-closed labels, abstention, citation
traceability, planner guards) is a methodology moat only if kept
ahead; the format itself is copyable. OEM integration (native backup
+ restore-test hooks, future UGREEN APIs) would be the real moat.
